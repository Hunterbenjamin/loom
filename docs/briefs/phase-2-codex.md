# Phase 2: `packages/adapters/codex`

**Agent:** codex · **Branch:** `feat/adapter-codex` · **PR title:** "Phase 2: Codex adapter". Read
[`phase-2-common.md`](phase-2-common.md) first, then spike 01's findings and its `client.ts`, which
is the starting point (transport: `ws+unix://<sock>:/rpc`, `Host: localhost`, no compression).

## Build

Implement `CodexAdapter` from `packages/core/src/adapters.ts` over the app-server protocol, with
bindings generated by `codex app-server generate-ts` (check the generated files in, pinned to the
Codex version).

- The adapter owns **one app-server process per task**, started by Loom outside the pane host with its
  own `CODEX_HOME` and socket (spike 05: that's what lets a turn survive a host restart). Add a
  `startServer`/`stopServer` pair to the interface and list it under "Contract changes".
- `generation`: increments on every reconnect; `answerRequest` rejects a stale generation, since
  request IDs restart with the server (spike 01).
- `startThread`, `startTurn`, `steerTurn` (with `expectedTurnId`), `interruptTurn`, `resumeThread`,
  `readThread`, `unsubscribe`, `readRateLimits`, `attachArgs`: as the interface says. `readThread`
  and `resumeThread` return a `CodexThreadObservation`, including `userMessageHashes` per turn
  (normalized text, sha256) so core can confirm steered delivery.
- Add a resumability check (`thread/read` on a fresh connection, distinguishing "not loaded" from
  "gone") and an activity timestamp source, for the `resumable` and `activityAt` fields the design
  requires. Contract changes.
- `subscribe`: notifications become hints; the adapter never acts on them.
- Approval requests arrive as server-initiated JSON-RPC requests; surface them as pending requests in
  the observation, never answer them yourself.

## Tests

Unit tests run against a fake app-server that replays recorded JSON-RPC traffic (spike 01's logs are
a start). Cover: initialize handshake, thread start and resume, steer with the wrong turn ID, a
pending approval visible in the snapshot, generation change on reconnect, interrupt, and rate-limit
parsing. Opt-in real tests use a private socket and the cheapest model, never the shared daemon.

## Out of scope

Rendering, the pane itself, and `review/start`.
